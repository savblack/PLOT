How it works

Three surfaces, one product. The marketing site (theplot.tv) is a hand-built static site — hero filmstrip, manifesto, interactive guide/lists/calendar demos, and a newsletter signup. Its one dynamic piece is /whats-on, a serverless proxy that fetches the marketing-feed edge function and re-serves it with proper HTML headers. The web app (app.theplot.tv) is the React/Vite SPA: a landing redirect, public/auth routes, and a protected shell whose child views are the product. The distribution channels — X, Instagram, Threads, the What's On feed, and the newsletter — are all fed by automation, never touched by hand.

Supabase is the shared backbone. Both surfaces lean on one Supabase project: auth with custom email templates, a Postgres schema with row-level security (profiles, journal, lists, watchlist, reminders, follows, Plex/Trakt integrations, and the marketing tables), storage for avatars and rendered cards, and 11 edge functions. The edge functions are where secrets live — tmdb-proxy keeps the TMDB key out of the browser, notify-feedback mirrors feedback into Linear off a Postgres webhook, and the AI features call Anthropic server-side.

Marketing runs itself. Five cron jobs drive Node scripts coordinated through the marketing tables. The daily loop plans exactly one post, generates Claude copy plus Playwright-rendered cards, emails a veto digest, and — only if that digest sent (fail-closed) — publishes ~12h later to every channel. X goes through Buffer's free tier, IG/Threads use the free Meta APIs, so the whole thing costs nothing per month.

Worth noting from the code: Plex and Trakt are first-class sync integrations (not just imports); marketing-feed is a public edge function but a marketing surface rather than an app feature; and public profiles (/u/:username) exist as a route but sharing is deferred for the first release.
